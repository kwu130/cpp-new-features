# 折叠表达式

折叠表达式用一个运算符归约参数包，取代 C++11 中常见的递归模板和展开技巧。

<!-- example id="cpp17-fold-expressions" std="c++17" file="main.cpp" kind="single" compilers="all" output="10" -->
```cpp
#include <iostream>

template <typename... Values>
auto sum(Values... values) {
    return (values + ... + 0);
}

template <typename... Conditions>
bool all(Conditions... conditions) {
    return (conditions && ...);
}

int main() {
    if (!all(true, 2 < 3, 4 == 4)) {
        return 1;
    }
    std::cout << sum(1, 2, 3, 4) << '\n';
}
```

一元折叠对空参数包只为 `&&`、`||` 和逗号运算符定义了单位值。需要支持空包时，像示例一样提供初始值。对非结合运算符还必须明确左折叠与右折叠的差异。

## 四种折叠形式

折叠可以是一元左折叠 `(... op pack)`、一元右折叠 `(pack op ...)`、二元左折叠 `(init op ... op pack)` 或二元右折叠 `(pack op ... op init)`。最外层括号是语法要求，不能省略。

对于参数 `a, b, c`，左折叠形成 `((a op b) op c)`，右折叠形成 `(a op (b op c))`。加法对普通整数看似无差别，但减法、除法、字符串拼接、流操作以及用户定义运算符可能产生不同结果。

二元折叠两侧出现的运算符必须相同，并且只有一侧能包含未展开参数包。初始表达式不是包的额外元素语法糖，它明确位于最终表达式树的一端：二元左折叠把初值放在最左侧，二元右折叠把初值放在最右侧。

<!-- example id="cpp17-fold-direction" std="c++17" file="main.cpp" kind="single" compilers="all" output="left=15, right=19" -->
```cpp
#include <iostream>

template <typename... Values>
int subtract_from_twenty(Values... values) {
    return (20 - ... - values);
}

template <typename... Values>
int subtract_toward_two(Values... values) {
    return (values - ... - 2);
}

int main() {
    const int left = subtract_from_twenty(3, 2);  // (20 - 3) - 2
    const int right = subtract_toward_two(20, 3); // 20 - (3 - 2)
    std::cout << "left=" << left << ", right=" << right << '\n';
}
```

两个函数都使用减号和三个数，但表达式树不同。代码评审时，给左右折叠手工展开两个或三个元素，往往比只记“省略号在哪边”更可靠。

## 空包与单位元

一元 `&&` 空包结果为 `true`，一元 `||` 为 `false`，逗号折叠为空表达式；其他一元运算符没有通用单位元。二元折叠显式给出 `init`，因此可以自然处理空包。示例的求和初始值 0 同时决定某些混合类型表达式的重载路径，应选与领域相符的单位元类型。

这里需要区分早期提案与最终 C++17 规则：最终标准只为一元 `&&`、`||` 和逗号折叠规定空包结果。若希望空包求和得到零、乘积得到一，必须使用二元折叠显式提供初值，不能依赖某个编译器对早期方案的实现。

初值还参与通常的重载解析和类型转换。例如 `(values + ... + std::string{})` 与 `(0 + ... + values)` 可能选择完全不同的运算符集合。库作者应让初值表达领域单位元，同时固定期望的结果类型。

## 求值顺序和短路

折叠保留所用运算符的求值规则。`&&`、`||` 会短路，逗号运算符保证顺序；普通算术运算符不要依赖未规定的操作数求值顺序。用折叠执行副作用时，优先选择语义明确的逗号折叠。

流插入常写成 `(std::cout << ... << values)`，这是一个以输出流为初值的二元左折叠。它依赖 `operator<<` 返回流引用，从而让下一次插入继续链式调用。若要在元素间加入分隔符，通常把单元素输出封装成 Lambda，再用逗号折叠控制顺序，比设计复杂的 `operator<<` 包装器更易维护。

对 `&&` 做能力检查时，短路发生在运行期；模板实例化阶段，包中每个操作数表达式仍需能够形成。要避免不合法表达式参与实例化，需要配合检测惯用法、SFINAE 或后续标准的 Concepts，而不是只依赖运行期短路直觉。

## 编译器实例化与成本

前端把折叠展开成普通表达式树，并为参与的重载执行解析。运行时没有“参数包循环对象”，优化器看到的是具体运算链。超长参数包仍会增加语义分析、表达式深度和生成代码体积。

相较递归函数模板，折叠通常减少辅助重载、递归终止版本和函数调用层级，也让诊断更接近原始表达式。但它不会减少包中每个元素对应的类型检查。用户定义运算符若每次返回不同包装类型，整个链仍可能实例化大量中间类型。

## 可用运算符与语法限制

折叠运算符来自一组固定的二元运算符，包括算术、位运算、比较、逻辑、移位、赋值、逗号以及成员指针运算符。条件运算符 `?:` 不是折叠运算符。模式必须满足 cast-expression 的语法层级；低优先级复合表达式有时需要额外括号。

折叠表达式必须整体置于括号中，这些括号属于语法而非风格选择。宏若接收含逗号的折叠表达式，仍会遇到预处理器参数分割问题，最好先封装进普通函数模板。

## 工程实践

选择左右方向时写下三元素展开结果进行确认；为空包定义明确语义；避免让运算符重载产生隐藏副作用；错误信息复杂时把单元素操作抽成命名函数，再对调用结果折叠。

## 模式与运算符优先级

fold 两侧要求 cast-expression 语法层级。若初始值或包模式顶层包含优先级低于 cast 的二元运算，必须额外括号，例如 `(args + ... + (1 * 2))`。最外层 fold 括号仍不可省略。

二元 fold 的两个运算符 token 必须相同，不能写“用加号折叠后再减初值”的混合形式。要组合不同运算，先把单元素模式封装成表达式/函数，再用一个 fold operator 归约。

包必须恰好出现在 fold 的一侧模式中；两侧都含同一/不同未展开包不合法。多个等长包若需要 zip，先在单一 expansion pattern 内组合对应元素，再折叠其结果。

### 赋值与成员指针折叠

赋值/复合赋值也在可用运算符集合中，但结合方向会显著改变被赋值对象。右折叠 `(targets = ... = value)` 等模式很难一眼证明，业务代码通常用逗号 fold 的命名操作更清晰。

`.*`/`->*` 可折叠成员指针链，适合极少数反射式适配。每一步左操作数类型必须是下一成员指针可应用对象，错误信息复杂，不应仅为展示语法使用。

比较 fold `(args < ...)` 不表达“严格递增序列”：展开是嵌套布尔比较，首个比较结果 bool 会再与下一元素比较。相邻有序检查应显式 zip/递归，不要误用比较运算符 fold。

## 值类别与返回结果

fold 展开后遵循每个运算符的返回类型和值类别。逗号 fold 的最终结果是最末表达式结果，流插入 fold 返回流引用，赋值 fold 返回左值；`auto` 接收可能复制，`decltype(auto)` 才精确保留。

包元素如果是转发引用，模式中应对每个元素 `std::forward<Args>(args)`；直接写具名 args 会全变左值。但每个参数通常只能安全 forward/消费一次，fold 内重复引用可能重复移动。

初始值的位置会影响重载解析。例如 string 拼接左侧必须先有 string 才能接某些字符指针组合。选择单位元不仅是数学值，还决定第一步静态类型。

## 诊断与编译规模

fold 消除了递归终止重载，却会形成一个可能很深的表达式树。超大包仍可能触发表达式深度、重载候选和调试信息成本，运行时也可能生成长直线代码。

把单元素操作约束/断言放进命名 helper，编译器可指出具体不满足的元素类型。直接在巨大 fold 中发生 operator 重载歧义，诊断通常包含整棵展开树。

若数据同质且数量运行期变化，容器循环/算法更合适；fold 用于编译期固定异构参数集合。

## 四种折叠形式速查

| 形式 | 结合方向/空包 |
| --- | --- |
| `(... op pack)` | 一元左折叠 |
| `(pack op ...)` | 一元右折叠 |
| `(init op ... op pack)` | 二元左折叠，init 在最左 |
| `(pack op ... op init)` | 二元右折叠，init 在最右 |
| `&&` 空包 | 标准单位值为 true |
| `||` 空包 | 标准单位值为 false |
| `,` 空包 | 结果为 void 表达式 |
| 其他一元空包 | 通常不合法，需提供 init |
| 运算符 | 同一 fold 的两个 op token 必须满足语法规则 |
| 求值副作用 | 由展开后的具体运算符顺序规则决定 |
