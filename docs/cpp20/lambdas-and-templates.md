# Lambda 与模板增强

C++20 允许 Lambda 使用显式模板参数列表，复杂泛型回调可以直接命名参数类型，并对它们施加约束。

<!-- example id="cpp20-lambda-templates" std="c++20" file="main.cpp" kind="single" compilers="all" output="6" -->
```cpp
#include <concepts>
#include <iostream>
#include <vector>

int main() {
    const auto sum = []<std::integral T>(const std::vector<T>& values) {
        T result{};
        for (const T value : values) {
            result += value;
        }
        return result;
    };

    std::cout << sum(std::vector<int>{1, 2, 3}) << '\n';
}
```

显式模板列表适合需要引用同一模板参数多次或添加约束的 Lambda；简单场景继续使用 `auto` 参数通常更清晰。

## 显式模板参数列表

C++14 泛型 Lambda 的每个 `auto` 参数对应隐式模板参数，却无法方便地命名其基础类型。C++20 允许在捕获列表后写 `[]<typename T>(...)`，其规则接近普通函数模板，可声明类型、非类型和参数包，并添加 Concepts 约束。

这使多个参数共享同一 T、显式取得数组长度、对参数包整体约束等模式更直接。闭包类型仍是唯一的匿名类，调用运算符成为成员函数模板；运行期没有新增反射信息。

显式列表位于捕获列表与函数参数列表之间：`[]<class T>(T value) { ... }`。它可以包含默认模板实参、非类型参数和参数包，并在参数列表后继续写 requires-clause。普通函数模板的推导、约束和显式模板实参规则大体适用到调用运算符。

泛型 Lambda 的调用运算符是模板，但闭包对象本身不是“函数模板变量”。需要显式指定模板实参时，可直接调用 `lambda.template operator()<Type>(args)`，不过频繁这样使用通常说明命名函数模板更清楚。

### 模板参数与函数参数共同推导

显式模板列表可以只声明一部分需要命名的参数，普通函数参数中的 `auto` 仍会引入额外发明模板参数。两组参数共同决定调用运算符模板特化。为了诊断清晰，关系密切的类型应放入显式列表并写出约束，纯转发的独立参数才保留 auto。

非类型参数可以从数组引用等函数形参推导，例如 `[]<std::size_t N>(const int (&)[N])`，让长度进入函数体常量。模板参数包可与函数参数包配对，但展开位置和长度仍遵守普通包规则，不是运行期可变参数。

尾部 requires-clause 可以引用显式模板参数、函数参数类型以及外围可见声明。约束只控制调用运算符候选，不会让闭包对象本身获得运行期标签。不同实参仍实例化不同调用运算符特化。

### 包展开初始化捕获

C++20 允许初始化捕获本身展开参数包，把每个传入对象分别变成闭包成员，适合构造拥有一组异构状态的局部任务。

<!-- example id="cpp20-lambda-pack-capture" std="c++20" file="main.cpp" kind="single" compilers="all" output="sum=6" -->
```cpp
#include <iostream>
#include <utility>

template <typename... Values>
auto make_sum(Values... values) {
    return [...stored = std::move(values)]() {
        return (stored + ... + 0);
    };
}

int main() {
    auto sum = make_sum(1, 2, 3);
    std::cout << "sum=" << sum() << '\n';
}
```

`stored` 是包展开的初始化捕获，每个 `values` 元素分别移动进对应闭包成员；调用时再对这些成员做折叠。闭包是否可复制取决于每个成员，若捕获 `unique_ptr` 等只移动对象，任务也只能移动。

包捕获避免先把异构对象装进显式 tuple 再 `apply`，但闭包成员名仍只在 Lambda 体内可用。需要公开遍历、序列化或稳定类型接口时，命名结构体更合适。

## 捕获 `this` 的演进

C++20 中在 `[=]` 下隐式捕获 `this` 被弃用，因为它表面像按值捕获，实际只复制指针。需要成员访问时应显式写 `[this]`，需要对象快照则使用 `[*this]`，并考虑复制成本与多态切片语义。

初始化捕获还可配合参数包展开，把一组对象分别移入闭包。每个捕获成员的可复制/可移动性质共同决定闭包特殊成员。

`[this]` 复制的是指针，闭包调用时对象必须仍存活；`[*this]` 复制当前对象形成闭包成员，之后成员访问针对副本。后者默认在 const 调用运算符中只读，若用 `mutable` 修改的是闭包副本而非原对象。

在多态基类成员函数中 `[*this]` 只按静态类型复制当前子对象，可能发生切片，不能当作“捕获完整动态对象”。异步成员任务通常显式捕获拥有型 `shared_ptr`，或由外部生命周期协议保证对象存在。

`[=, this]` 在 C++20 成为允许的显式写法，用来强调其余变量按值而对象仍按指针捕获。`[=]` 隐式捕获 `this` 被弃用，迁移时应根据所有权意图选择 `[this]` 或 `[*this]`，而不是机械加语法。

## 捕获与闭包特殊成员

无捕获 Lambda 在 C++20 可默认构造并可复制赋值，这让它更容易作为无状态策略类型用于容器和算法。它还能转换为相应函数指针；带捕获 Lambda 仍不能做这种普通转换。

每个 Lambda 表达式产生唯一闭包类型，即便两个表达式文本相同，类型也不同。C++20 允许 Lambda 出现在更多未求值语境，使 `decltype([] { ... })` 能直接形成模板实参等类型工具，但每个源表达式的类型身份仍独立。

捕获成员的初始化顺序和具体成员名不应被程序依赖。引用捕获是否以成员形式存储是实现细节，但被引用实体必须在每次调用时存活。按值捕获默认是闭包构造时快照，对外部变量后续修改不可见。

`mutable` 只移除调用运算符默认的 const 限定，使按值捕获成员可修改；它不会让引用捕获绕过原对象 const，也不会自动同步多线程调用同一闭包对象。

无捕获 Lambda 的函数指针转换会选择与目标签名匹配的调用运算符；对泛型无捕获 Lambda，这可能实例化一个具体特化。转换后只剩该签名，不再保留“可以接受多种类型”的泛型能力，也不再携带闭包对象状态。

闭包具体布局、捕获成员名称与成员排列不构成稳定 ABI。不能 memcpy 闭包做持久化，也不能把不同编译器构建的闭包对象当作二进制协议。即使两个 Lambda 文本相同，它们的唯一类型身份也不同。

模板 Lambda 的多个 operator() 特化调用同一个闭包对象并共享捕获状态。若闭包为 mutable，一个 `int` 特化对捕获计数器的修改，会被后续 `double` 特化调用观察到；模板实例独立不等于对象状态独立。

## 模板 Lambda 作为局部算法

显式模板 Lambda 很适合只在一个函数内使用的类型算法，避免为小逻辑创建命名辅助模板。若约束、重载或文档需求增长，应提升为命名 Concept 和函数，防止局部表达式变成难以诊断的大型模板。

模板 Lambda 可递归地把自身作为参数传入，或捕获外层模板上下文；但错误堆栈会同时包含匿名闭包和调用运算符模板。给局部变量取语义名称、把约束抽成 Concept，能显著改善诊断。

作为 ranges 适配器的谓词时，闭包会存进 View 类型。捕获引用带来悬空风险，捕获大对象增加管道大小，mutable 状态还可能让多遍迭代结果变化。局部方便性不能替代生命周期设计。

局部模板 Lambda 还能访问外围函数的模板参数与局部类型，适合只在一个算法中出现的访问器。代价是错误诊断会同时包含外围模板、闭包类型和 operator() 特化层；逻辑超过少量分支时，提取命名函数对象能显著改善错误位置。

把模板 Lambda 存入 `std::function<R(Args...)>` 会固定一个具体调用签名并做类型擦除，其他潜在 operator() 特化不会作为开放接口保留。需要让下游以多种类型调用，应继续通过模板传递闭包，或定义明确的 variant/虚拟协议。

## 与普通函数模板的选择

Lambda 擅长靠近调用点、捕获局部状态和一次性组合；命名函数模板擅长多处复用、文档、重载集合、显式实例化和稳定诊断。逻辑超过几个分支、需要单独测试或成为 API 时，应升级为命名实体。

无捕获模板 Lambda 可以作为编译期策略对象传递，避免函数指针丢失内联信息。若需要运行期异构存储，再考虑 `std::function` 等类型擦除；直接套一层 `function` 会失去泛型调用运算符的多类型能力。

## 示例解析与成本

示例把参数约束为 `integral`，并在函数体内以同一 T 保存累加结果。每种整数向量类型会实例化独立调用运算符，编译器通常内联循环。大量不同 T 仍会导致模板代码膨胀，应与普通命名模板一样关注构建成本。

## 工程检查清单

简单独立参数用 `auto`；需要复用类型名或约束时用显式列表；长期闭包明确 `this` 所有权；接口级逻辑优先命名模板；为约束失败和大对象捕获添加测试与性能检查。
