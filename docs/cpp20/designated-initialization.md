# 指定初始化

指定初始化用成员名初始化聚合对象，配置结构体因此更易读，也不再依赖读者记住每个值的位置。

<!-- example id="cpp20-designated-initialization" std="c++20" file="main.cpp" kind="single" compilers="all" output="localhost:8080 secure=false" -->
```cpp
#include <iostream>
#include <string>

struct ServerConfig {
    std::string host;
    int port = 80;
    bool secure = false;
};

int main() {
    const ServerConfig config{
        .host = "localhost",
        .port = 8080,
        .secure = false,
    };
    std::cout << config.host << ':' << config.port
              << " secure=" << std::boolalpha << config.secure << '\n';
}
```

C++20 要求指示符遵循成员声明顺序，且只适用于聚合类型；它不同于允许任意顺序的某些语言扩展。

## 聚合类型前提

指定初始化建立在聚合初始化之上。聚合大致是允许成员直接按声明结构初始化的数组或类，不能具有破坏聚合条件的用户声明构造函数等特征；精确定义随标准演进。给配置结构新增构造函数可能让已有指定初始化调用全部失效。

每个指示符必须命名当前类的直接非静态数据成员，不能指定基类成员、嵌套路径或同一成员两次。未指定成员按默认成员初始化器初始化，否则执行空列表初始化。

## 顺序要求的原因

C++ 对象成员始终按声明顺序初始化，而不是按初始化列表书写顺序。C++20 要求指示符也保持声明顺序，避免源码顺序与真实构造顺序产生错觉，并简化聚合初始化模型。

这意味着在结构体中间插入新成员通常不破坏只指定前后兼容顺序的调用，但移动成员声明可能导致编译错误。配置类型的成员顺序因此也成为一定程度的源代码接口。

## 默认值与演进

指定初始化很适合带合理默认值的参数对象：调用点只写与默认不同的字段，比长位置参数清晰。新增带默认值的尾部成员通常兼容，新增必须设置却无类型级约束的字段可能被旧调用静默遗漏。

若必须保证某字段存在，应使用构造函数、工厂或强类型构建器，而不是仅依赖代码审查发现未指定成员。

## 底层与成本

它只是初始化语法，不保存字段名或运行期映射。编译器仍按普通成员布局直接构造，通常没有额外成本。字段名提升的是源代码可读性，不提供反射或序列化能力。

## 示例解析与实践

示例按声明顺序设置三个字段。工程中保持配置聚合简单、提供安全默认、避免成员重排，并用测试验证默认组合；需要复杂不变量时升级为构造函数或具名工厂。
