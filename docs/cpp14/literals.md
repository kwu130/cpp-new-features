# 二进制字面量与数字分隔符

二进制字面量适合表达位掩码，单引号数字分隔符提高长数字的可读性且不改变数值。

<!-- example id="cpp14-literals" std="c++14" file="main.cpp" kind="single" compilers="all" output="mask=165, population=1000000" -->
```cpp
#include <iostream>

int main() {
    const unsigned mask = 0b1010'0101;
    const int population = 1'000'000;
    std::cout << "mask=" << mask << ", population=" << population << '\n';
}
```

分隔符可以出现在整数和浮点字面量的数字之间，但不能紧邻小数点或指数标记。位操作仍应优先使用无符号类型，避免有符号移位带来的边界问题。

## 词法与类型规则

二进制字面量以前缀 `0b` 或 `0B` 开始，之后只能出现二进制数字和合法分隔符。它与十六进制、八进制字面量一样先形成整数常量，再根据数值、进制和后缀规则选择能表示该值的整数类型。

单引号只是词法分隔符，不进入数值，也不要求固定分组。`0b1010'0101` 按半字节分组便于与十六进制对照，`1'000'000` 按千位分组便于阅读。分组应服务于领域含义，位字段可以按协议段而非四位分组。

## 编译器与运行时成本

词法分析阶段会忽略合法分隔符，并把不同进制文本解析成同一整数值。目标代码中不存在“二进制字面量格式”，因此不会产生额外运行成本，也不会让输出自动变成二进制格式。

位掩码的类型仍然重要。没有后缀的较大字面量可能推导成实现相关的有符号或无符号整数类型；需要精确宽度时使用 `UINT32_C`、固定宽度类型转换或合适后缀，并检查目标类型是否存在。

## 常见错误与实践

- `0b` 是数字零加字母 b，不是字母 O。
- 分隔符不能连续出现，也不能紧邻前缀、后缀、小数点或指数标记。
- 二进制书写不会自动防止移位越界和整数提升。
- 协议位字段建议同时定义具名掩码、位位置和静态断言，而不是在业务代码散落魔法数字。

示例中的两个字面量在编译后分别就是整数 165 与 1000000；其价值完全在源代码可读性和审查准确度。
