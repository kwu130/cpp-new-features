# 类定义能力增强

C++11 可以显式默认或删除特殊成员函数，并通过 `override`、`final` 让继承意图接受编译器检查。委托构造和继承构造减少了重复初始化逻辑，`enum class` 避免枚举值污染外围作用域。

<!-- example id="cpp11-class-improvements" std="c++11" file="main.cpp" kind="single" compilers="all" output="worker:7" -->
```cpp
#include <iostream>
#include <string>

enum class Role { guest, worker };

class Entity {
public:
    explicit Entity(int id) : id_(id) {}
    virtual ~Entity() = default;
    virtual std::string name() const = 0;
    int id() const { return id_; }

private:
    int id_;
};

class Worker final : public Entity {
public:
    using Entity::Entity;
    std::string name() const override { return "worker"; }
    Worker(const Worker&) = delete;
    Worker& operator=(const Worker&) = delete;
};

int main() {
    Worker worker(7);
    const Role role = Role::worker;
    if (role == Role::worker) {
        std::cout << worker.name() << ':' << worker.id() << '\n';
    }
}
```

对所有虚函数重写使用 `override`。只有明确禁止继承或重写时才使用 `final`。删除函数不仅适用于复制操作，也可用于阻止不希望发生的隐式类型转换。

## 显式表达编译器生成行为

特殊成员函数包括默认构造、析构、复制构造、复制赋值、移动构造和移动赋值。过去开发者常声明私有但不实现的复制函数来禁止复制，错误直到链接或访问检查才暴露。`= delete` 把禁用行为放进重载集合，并在调用点给出明确编译错误。

`= default` 要求编译器按语言规则生成函数，同时允许开发者控制可见性、虚函数性质或声明位置。显式默认并不保证函数一定可用：若成员本身不可复制，对应默认复制函数仍会被定义为删除。

声明某些特殊成员会抑制其他成员的隐式生成。例如用户声明析构函数通常意味着编译器不再隐式生成移动操作。资源类应逐项审查，或更优先把资源交给标准 RAII 成员，遵循零法则。

### 六个特殊成员的生成关系

默认构造函数只在没有用户声明构造函数时隐式声明。复制构造/赋值有各自隐式规则；移动构造/赋值只在没有用户声明复制操作、移动操作或析构等条件满足时生成。一个看似无害的空析构会让 vector 回退复制。

`= default` 在首次声明处与在类外稍后默认化，对 trivial、constexpr/noexcept 和用户提供函数判定可能有差异。追求平凡类型/ABI 时应查精确规则，不能只看最终函数体都由编译器生成。

默认函数的异常说明由成员/基类对应操作合成。若某成员移动会抛，默认移动也可能抛，容器因此选择复制。给外层盲目写 noexcept 会在成员抛出时终止。

删除复制构造不自动代表移动存在；用户声明 delete 本身也参与抑制规则。需要 move-only 类型应明确声明移动，或让 unique_ptr 等成员配合零法则自然生成。

### Rule of Zero/Five

拥有裸资源的类通常要同时设计析构、复制/移动构造、复制/移动赋值，即五法则。遗漏一个会产生浅复制、双释放或性能退化。更推荐把资源交给 unique_ptr/vector/string 等成员，让外层不声明任何特殊成员（零法则）。

多态基类常需要虚析构，这会影响隐式移动；可以显式 default 移动或根据身份语义 delete 复制/移动。每个选择都应由接口不变量驱动，而不是机械补齐五个函数。

## 虚函数检查的底层意义

没有 `override` 时，参数 cv 限定、引用限定或拼写差异可能让派生类意外声明新虚函数。`override` 使编译器验证基类确有可覆盖槽位；它通常不改变虚表布局或调用成本，只增加静态检查。

`final` 允许编译器知道某个类不能再派生或某个虚函数不能再覆盖。在可见动态类型的优化场景，编译器可能据此去虚拟化，但性能不是使用 `final` 的主要理由，设计约束才是。

override/final 是 contextual keyword，只在相应声明位置具有特殊含义，旧代码仍可在其他上下文使用同名标识符。风格上把它们放在函数声明尾部并避免再重复写 virtual，可突出覆盖意图。

覆盖要求参数类型、cv 限定和引用限定匹配，并满足返回类型相同或协变。默认参数不参与虚派发：它由静态类型选择，因此基类/派生类给不同默认值会产生令人意外结果，override 不会禁止。

虚函数调用在构造/析构期间不会派发到尚未构造/已析构派生部分。override 只验证槽位，不改变对象生命周期规则。不要在基类构造中依赖派生实现。

私有基类虚函数也能被派生类覆盖，因为访问控制与覆盖关系分开；调用是否可访问再按静态接口检查。给所有覆盖加 override 能明确这种不直观关系。

## 构造函数复用

委托构造让一个构造函数调用同类的另一个构造函数，集中维护不变量；完成被委托构造后才执行当前构造函数体。委托链不能形成环。

`using Base::Base` 把基类构造函数引入派生类重载集合，但不会自动解决派生类新增成员的业务初始化。新增成员仍按默认成员初始化器或默认初始化规则处理。

继承构造函数不等于复制/移动派生对象的构造函数，也不会继承析构函数。若某个基类构造签名与派生复制/移动候选冲突，语言有专门规则；仍需检查最终重载集。

基类构造完成后才初始化派生新增成员（按正常顺序）。若成员没有默认成员初始化器且默认初始化不安全，引入基类构造会制造未初始化状态。继承前先给派生不变量完整默认。

访问级别按继承构造规则处理，不能仅凭 using 所在 public 区就假定所有基类私有构造对外可用。最终构造可访问性由被选基类构造等规则决定。

委托构造异常时，目标构造若未完成则对象未构造；若目标已完成、委托函数体随后抛出，完整对象成员会析构。不能在委托链中读尚未由目标建立的状态。

## `enum class` 的类型安全

作用域枚举的枚举项必须通过 `Role::worker` 访问，不会泄漏到外围作用域，也不会隐式转换为整数。底层整数类型可显式指定，便于协议布局；转成整数必须使用显式转换。

普通 enum C++11 也可指定固定底层类型，但枚举项仍注入外围作用域并可隐式转整数。enum class 同时解决作用域和强类型，不只是换一种访问拼写。

底层类型决定表示范围，不保证每个底层整数都对应已声明 enumerator。反序列化 `static_cast<Role>(raw)` 后仍要验证 raw 是否属于有效集合，类型系统不会自动拒绝未知值。

不同 enum class 即使底层类型相同也不能互比/互赋，避免把不同领域状态混用。需要位标志时可为特定枚举定义显式 `operator|/&`，不要恢复所有整数隐式操作。

前置声明 scoped enum 可写 `enum class Status;`（默认底层 int）或指定底层，便于减少头文件依赖。声明和定义底层类型必须一致。

## 示例解析与检查清单

示例把抽象基类析构设为虚函数，用 `override` 锁定重写关系，以 `final` 表达 Worker 不再作为扩展点，并删除复制操作表达身份对象不可复制。设计类时应分别回答：它是否拥有资源、能否复制、移动后状态如何、是否用于多态删除、继承是否真的是稳定扩展机制。

## 委托构造与默认成员初始化

委托构造函数只能在成员初始化列表中选择同一个类的另一个构造函数。一旦选择委托目标，当前构造函数不能再直接初始化其他成员；目标构造完成后才执行当前函数体。这能把参数校验和不变量集中到一个主构造函数。

C++11 默认成员初始化器为没有在构造函数列表中显式初始化的成员提供默认值。它与委托构造配合时，可以减少每个构造函数重复写相同默认状态。若构造函数显式初始化某成员，显式项优先。

<!-- example id="cpp11-delegating-enum-class" std="c++11" file="main.cpp" kind="single" compilers="all" output="port=8080, code=2" -->
```cpp
#include <cstdint>
#include <iostream>

enum class ErrorCode : std::uint8_t {
    none = 0,
    unavailable = 2
};

class ServerConfig {
public:
    ServerConfig() : ServerConfig(8080) {}
    explicit ServerConfig(int port) : port_(port) {}
    int port() const { return port_; }

private:
    int port_;
};

int main() {
    const ServerConfig config;
    const ErrorCode code = ErrorCode::unavailable;
    std::cout << "port=" << config.port()
              << ", code=" << static_cast<int>(code) << '\n';
}
```

显式底层类型适合协议和存储布局，但枚举对象的实际大小与 ABI 仍应在目标平台验证。`enum class` 不隐式转整数，因此协议编码必须显式转换，也应检查值是否落在有效枚举集合。

## `default` 与 `delete` 的重载影响

删除函数仍参与重载解析；如果它是最佳匹配，程序会在调用点报“使用已删除函数”，而不是退而选择更差的转换。这使 `void process(double) = delete;` 可以明确禁止浮点输入。默认函数则保留编译器生成语义，并允许调整可见性或在类外定义。

删除任意函数都可以，不限特殊成员：可删除不安全转换模板、某些参数类型甚至 `operator new`。但过宽模板 delete 可能抢占预期重载，要用编译测试覆盖候选集。

删除析构函数会让对象难以在普通作用域创建/销毁，适用于极少数静态接口类型；仅想禁止栈创建通常用私有析构/工厂并明确所有权。delete 是强约束，错误不会回退。

默认化比较等能力属于后续标准，C++11 `= default` 主要用于特殊成员。不要把 C++20 `operator<=> = default` 混入本章。

## 类语法速查

| 语法 | 作用/边界 |
| --- | --- |
| `enum class E` | 强作用域枚举，不隐式转普通整数 |
| `enum class E : uint8_t` | 显式底层类型，仍需检查序列化协议 |
| `C() : C(args) {}` | 委托给同类另一构造函数，目标先完成 |
| `using Base::Base` | 继承构造函数，不自动解决派生额外不变量 |
| `f() = default` | 请求编译器生成，删除状态仍由成员决定 |
| `f() = delete` | 让候选参与解析后明确拒绝，可禁转换/复制 |
| `override` | 要求确实覆盖某个基类虚函数 |
| `final` 函数 | 禁止更下层覆盖该虚函数 |
| `final` 类 | 禁止继续派生，不等于自动去虚拟化承诺 |
| 类内成员初值 | 构造函数未显式初始化该成员时采用默认值 |

## 类改进专项审查

- enum class 底层类型是否满足协议且转换显式？
- 委托构造是否形成直接/间接循环？
- 委托目标完成后函数体是否再次破坏不变量？
- 继承构造是否遗漏派生类新增成员验证？
- default 后函数是否因成员不可用而仍被删除？
- delete 重载是否产生比私有声明更清晰的拒绝？
- 每个预期覆盖是否都标记 override？
- final 是否真表达封闭设计而非临时阻止扩展？
- 类内成员默认值是否被某构造函数显式覆盖？
- 新成员是否改变隐式复制/移动生成规则？
